# Prism Constraint History

### 2026-07-28 — SuperSwingTimer Addon — Full Prism v3 (Corrected Architecture)
- **Deepest finding:** SoD.lua can be a fully self-contained module with **zero base-code modifications**. Every SoD feature can use existing extension points: `addSpellIds()` to inject into swing classification tables, `ns.RegisterOnUpdateHook()` for per-frame callbacks, `ns.RegisterSpellcastSucceededHook()` for spellcast hooks, nil-safe callback assignments (`ns.UpdateRogueEnergyBar = function... end`), and `UnitBuff("player", <SoD spell ID>)` which returns nil on Classic/TBC (automatic nil-safety). The optional one line in Weaving.lua (`local extra = ns.weaveExtraMultiplier or 1`) would cleanly integrate Maelstrom weave adjustments but is avoidable by overriding the display layer.
- **Maximized:** Extension point map (15 points, 14 existing), SoD.nil-safe injection pattern verified across Classic Era, TBC Anniversary, and SoD clients, Maelstrom Weapon `UnitBuff` polling approach (avoids CLEU hook entirely), per-class power bar frame creation gated by `GetSpellInfo()` check (zero overhead on Classic/TBC)
- **Sacrificed:** Warlock tank (Metamorphosis) melee consideration — no swing timer needed for caster classes on SoD. Maelstrom Weapons exact stack coefficient verification against WoW API (assumed 20% reduction based on SoD theorycraft). Phase 4+ SoD rune content (Cloak, Ring 1, Ring 2 slots)
- **Retracted:** Base-code CLEU hook (unnecessary — `UnitBuff` polling works). SPELL_AURA_APPLIED_DOSE handler (same — polling handles stack detection)
- **Extension points used:** `addSpellIds()` (SoD.lua local helper), `ns.RegisterOnUpdateHook()` (Hooks.lua), `ns.RegisterSpellcastSucceededHook()` (State.lua), nil-safe callback overrides (`ns.UpdateWarriorRageBar`, `ns.OnMeleeSwing`), `ns.spellcastSucceededHooks` table, `ns.WARRIOR_OVERPOWER_ID`/`ns.HUNTER_READINESS_ID`/`ns.ROGUE_ADRENALINE_RUSH_ID` constants, swing classification lookup tables (`NO_RESET_SWING`, `RESET_SWING`, `PAUSE_SWING`), `DRUID_FORM_IDS` table
- **Final consensus:** The addon's existing extension point architecture is complete enough to support all SoD features without base-code modifications. The unitary power bar is a base-code issue (predates SoD) and should be fixed in ClassMods.lua as a separate task. SoD.lua handles all SoD-specific power bar overrides.

### Conservation Laws
1. **Table entry × CLEU event = Constant.** A spell affects behavior only when its ID is in a lookup table AND it fires in a CLEU event. SoD.lua provides the entry; the client provides (or withholds) the event. The two gates are orthogonal and both are nil-safe.
2. **Frame creation × Client check = Constant.** Creating a StatusBar is cheap (~200 bytes). Gating it behind `if GetSpellInfo(sodSpellId) then` ensures zero overhead on clients that don't need it. Same pattern applies to every UI element.
